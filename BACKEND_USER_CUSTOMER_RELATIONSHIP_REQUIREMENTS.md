# 🔗 **Backend Requirements: User-Customer Relationship System**

## 📋 **Overview**

This document outlines the backend requirements for implementing a user-customer relationship system that allows multiple customers to be assigned to users, enabling data filtering based on user assignments.

## 🗄️ **Database Schema Changes**

### **1. New Table: User Customer Assignments**

Based on the existing schema structure, create the following table:

```sql
-- User Customer Assignments Table
CREATE TABLE IF NOT EXISTS public."USER_CUSTOMER_ASSIGNMENT"
(
    id bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY ( INCREMENT 1 START 1 MINVALUE 1 MAXVALUE 9223372036854775807 CACHE 1 ),
    created_on timestamp with time zone NOT NULL,
    created_by integer,
    modified_on timestamp with time zone,
    modified_by integer,
    user_id bigint NOT NULL,
    customer_id bigint NOT NULL,
    assigned_by bigint,
    assigned_on timestamp with time zone DEFAULT CURRENT_TIMESTAMP,
    is_active boolean NOT NULL DEFAULT TRUE,
    CONSTRAINT "USER_CUSTOMER_ASSIGNMENT_pkey" PRIMARY KEY (id),
    CONSTRAINT "USER_CUSTOMER_ASSIGNMENT_user_customer_unique" UNIQUE (user_id, customer_id)
);

-- Foreign Key Constraints
ALTER TABLE IF EXISTS public."USER_CUSTOMER_ASSIGNMENT"
    ADD CONSTRAINT "USER_CUSTOMER_ASSIGNMENT_user_id_fk" FOREIGN KEY (user_id)
    REFERENCES public."user" (id) MATCH SIMPLE
    ON UPDATE NO ACTION
    ON DELETE CASCADE
    DEFERRABLE INITIALLY DEFERRED;

ALTER TABLE IF EXISTS public."USER_CUSTOMER_ASSIGNMENT"
    ADD CONSTRAINT "USER_CUSTOMER_ASSIGNMENT_customer_id_fk" FOREIGN KEY (customer_id)
    REFERENCES public."CUSTOMER" (id) MATCH SIMPLE
    ON UPDATE NO ACTION
    ON DELETE CASCADE
    DEFERRABLE INITIALLY DEFERRED;

ALTER TABLE IF EXISTS public."USER_CUSTOMER_ASSIGNMENT"
    ADD CONSTRAINT "USER_CUSTOMER_ASSIGNMENT_assigned_by_fk" FOREIGN KEY (assigned_by)
    REFERENCES public."user" (id) MATCH SIMPLE
    ON UPDATE NO ACTION
    ON DELETE SET NULL
    DEFERRABLE INITIALLY DEFERRED;

-- Indexes for Performance
CREATE INDEX IF NOT EXISTS "USER_CUSTOMER_ASSIGNMENT_user_id_idx"
    ON public."USER_CUSTOMER_ASSIGNMENT"(user_id);

CREATE INDEX IF NOT EXISTS "USER_CUSTOMER_ASSIGNMENT_customer_id_idx"
    ON public."USER_CUSTOMER_ASSIGNMENT"(customer_id);

CREATE INDEX IF NOT EXISTS "USER_CUSTOMER_ASSIGNMENT_active_idx"
    ON public."USER_CUSTOMER_ASSIGNMENT"(is_active);

CREATE INDEX IF NOT EXISTS "USER_CUSTOMER_ASSIGNMENT_user_active_idx"
    ON public."USER_CUSTOMER_ASSIGNMENT"(user_id, is_active);
```

### **4. Role Privilege Assignment**

Assign privileges to existing roles in the `ROLE_PRIVILEGE` table:

```sql
-- Get privilege IDs for assignment
-- Admin Role (Role ID: 1) - Full access to all user-customer relationship operations
INSERT INTO public."ROLE_PRIVILEGE" ("ROLE_ID", "PRIVILEGE_ID", created_on, created_by)
SELECT 1, id, CURRENT_TIMESTAMP, 1
FROM public."MASTER_PRIVILEGE" 
WHERE "PRIVILEGE_NAME" IN (
    'CREATE_CUSTOMER', 'UPDATE_CUSTOMER', 'DELETE_CUSTOMER', 'VIEW_CUSTOMER_LIST', 'VIEW_CUSTOMER_DETAILS',
    'ASSIGN_CUSTOMERS_TO_USER', 'REMOVE_CUSTOMERS_FROM_USER', 'ASSIGN_USERS_TO_CUSTOMER', 'REMOVE_USERS_FROM_CUSTOMER',
    'VIEW_USER_CUSTOMER_ASSIGNMENTS', 'MANAGE_USER_CUSTOMER_RELATIONSHIPS', 'BULK_ASSIGN_CUSTOMERS', 'BULK_ASSIGN_USERS',
    'CUSTOMER_DATA_FILTERING', 'USER_CUSTOMER_AUDIT', 'RELATIONSHIP_NOTIFICATIONS', 'BULK_RELATIONSHIP_OPERATIONS'
);

-- Manager Role (Role ID: 2) - Limited access to user-customer relationships
INSERT INTO public."ROLE_PRIVILEGE" ("ROLE_ID", "PRIVILEGE_ID", created_on, created_by)
SELECT 2, id, CURRENT_TIMESTAMP, 1
FROM public."MASTER_PRIVILEGE" 
WHERE "PRIVILEGE_NAME" IN (
    'VIEW_CUSTOMER_LIST', 'VIEW_CUSTOMER_DETAILS', 'VIEW_USER_CUSTOMER_ASSIGNMENTS',
    'ASSIGN_CUSTOMERS_TO_USER', 'REMOVE_CUSTOMERS_FROM_USER', 'CUSTOMER_DATA_FILTERING', 'RELATIONSHIP_NOTIFICATIONS'
);

-- Regular User Role (Role ID: 3) - Read-only access to their own assignments
INSERT INTO public."ROLE_PRIVILEGE" ("ROLE_ID", "PRIVILEGE_ID", created_on, created_by)
SELECT 3, id, CURRENT_TIMESTAMP, 1
```

## 🔒 **Security & RBAC Implementation**

### **1. Permission Validation**

Each endpoint must validate:
- User has the required privilege
- User can only assign customers they have access to
- User can only view assignments they have permission for
- Superusers bypass all restrictions

### **2. Data Filtering Logic**

```typescript
// Customer data filtering based on user assignments
const getFilteredCustomers = async (userId: number, userRole: number, filters: any) => {
  if (userRole === 1) { // Admin - see all customers
    return await getAllCustomers(filters);
  } else {
    // Regular users - only see assigned customers
    return await getCustomersByUserAssignment(userId, filters);
  }
};

// User data filtering based on customer assignments
const getFilteredUsers = async (customerId: number, userRole: number, filters: any) => {
  if (userRole === 1) { // Admin - see all users
    return await getAllUsers(filters);
  } else {
    // Regular users - only see users assigned to their customers
    return await getUsersByCustomerAssignment(customerId, filters);
  }
};
```

### **3. Audit Logging**

All assignment operations must log to `USER_CUSTOMER_AUDIT_LOG`:
- Assignment creation
- Assignment removal
- Bulk operations
- Failed operations
